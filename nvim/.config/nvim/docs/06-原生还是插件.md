# 06 · 这个功能是原生还是插件？

你说过 LazyVim 里很多功能像魔法，分不清是插件还是 Neovim 自带的。
这份文档就是那张地图。

**判断方法（30 秒）：**

```vim
:verbose map <某个键>       " 告诉你这个键在哪个文件第几行定义
```

- 输出里有 `/home/umbrella/.config/nvim/...` → 是我们配的
- 输出里有 `site/pack/core/opt/...` → 是插件的
- 输出里有 `/usr/share/nvim/runtime/...` 或什么都不显示 → **Neovim 原生**

---

## 一、你以为是插件，其实是 Neovim 原生的

这一节是重点。以下功能**全部不需要任何插件**，LazyVim 只是替你开了开关。

### 编辑操作

| 功能 | 键位 | 从哪个版本起 |
|---|---|---|
| 注释切换 | `gcc` `gc`+范围 | 0.10 |
| 复制时高亮闪一下 | 自动 | 0.11（默认开启） |
| 替换命令实时预览 | `:%s/a/b` 时自动 | 0.8 |
| 代码片段展开与跳转 | `vim.snippet` | 0.10 |
| EditorConfig 支持 | 自动 | 0.9 |
| 持久化撤销 | `undofile` 选项 | 很早 |
| 大文件自动降级 | 自动 | 0.11 |

### `]` / `[` 跳转系列

**0.11 起 Neovim 内置了一大批**，以前要装 unimpaired.vim：

```
]d [d  诊断        ]q [q  quickfix     ]b [b  buffer
]t [t  标签页      ]f [f  同目录文件   ]a [a  参数列表
]<Space> [<Space>  在上/下方插入空行
```

完整列表：`:help ]`

注意：`]e`/`[e`（只跳错误、跳过警告）**不是**原生的，是本配置在
`lua/core/diagnostic.lua` 里加的。

### LSP 相关

| 功能 | 键位 / API | 从哪个版本起 |
|---|---|---|
| 看文档悬浮窗 | `K` | 0.11 默认键位 |
| 重命名符号 | `grn` | 0.11 默认键位 |
| 代码修复建议 | `gra` | 0.11 默认键位 |
| 找所有引用 | `grr` | 0.11 默认键位 |
| 跳到实现 | `gri` | 0.11 默认键位 |
| 跳到类型定义 | `grt` | 0.11 默认键位 |
| 看完整诊断 | `<C-w>d` | 0.11 默认键位 |
| **自动补全弹窗** | `vim.lsp.completion.enable` | 0.11 |
| 行内类型提示 | `vim.lsp.inlay_hint` | 0.10 |
| 诊断显示为虚拟行 | `virtual_lines` | 0.11 |
| **配置 language server** | `vim.lsp.config` / `vim.lsp.enable` | 0.11 |

**最后一条尤其重要**：以前所有人都装 `nvim-lspconfig`，
0.11 之后配一个 server 只要建一个 `lsp/<名字>.lua` 文件，十来行。
本配置就是这么做的，没装那个插件。

### 语法高亮

| 功能 | 说明 |
|---|---|
| treesitter 高亮引擎 | **Neovim 内置**（`vim.treesitter.start()`） |
| 内置的语言 parser | `c` `lua` `vim` `vimdoc` `markdown` `query` |
| 语法折叠 | `vim.treesitter.foldexpr()` |
| 下载其他语言的 parser | ← **这个才需要插件**（nvim-treesitter） |

所以：**写 C 和 Markdown 时，就算删掉所有插件也有完整高亮。**

### 插件管理器本身

`vim.pack`，0.12 起自带。所以本配置**没装 lazy.nvim**。
详见 [02-插件层.md](02-插件层.md)。

### 其他

| 功能 | 说明 |
|---|---|
| 终端 | `:terminal`，本配置的 lazygit 就是用它实现的 |
| 文件浏览 | netrw（`:Explore`）—— 简陋，所以我们用 mini.files 替代 |
| 模糊查找文件 | `:find` + `path+=**` + wildmenu —— 不能搜内容，所以用 fzf-lua |
| 外部改动自动重载 | `autoread` |
| 括号匹配高亮 | 内置 matchparen 插件 |
| diff 模式 | `:diffthis` `vimdiff` |
| 会话保存 | `:mksession` |
| 拼写检查 | `spell` 选项 |
| 帮助文档搜索 | `:helpgrep` |
| man page 阅读 | `:Man` |
| quickfix 列表 | `:copen`，是 Vim 几十年前就有的核心机制 |

## 二、这个配置里，插件负责什么

只有 8 个插件，每个的职责边界很清楚：

| 插件 | 它做的事 | 它**不**做的事 |
|---|---|---|
| catppuccin | 提供配色 | — |
| nvim-treesitter | 下载语言 parser | 高亮（那是原生的） |
| fzf-lua | 模糊查找的界面和交互 | 实际搜索（交给 fzf/ripgrep 命令） |
| gitsigns | 行内 git 标记、hunk 操作 | git 本身的操作（用 lazygit） |
| mini.files | 文件浏览器界面 | — |
| mini.surround | `sa`/`sd`/`sr` 三个操作 | — |
| which-key | 按键提示弹窗 | 定义键位（键位是我们自己写的） |
| conform | 调用格式化工具的统一入口 | 格式化本身（交给 clang-format 等命令） |

**注意后两个的特点**：which-key 只是显示提示，键位全是配置里自己写的；
conform 只是个调度器，真正格式化的是 clang-format。
所以删掉它们，功能不会消失，只是用起来麻烦点。

## 三、LazyVim 里有但这里没有的

如果你怀念某个功能，可以告诉我加回来。列在这里是为了让你知道**它确实不存在**，
而不是你没找到。

| LazyVim 的东西 | 这里的替代 |
|---|---|
| 启动页（dashboard/snacks） | 无。`nvim` 直接进空 buffer |
| buffer 顶栏（bufferline） | 无。用 `<leader><leader>` 或 `<S-h>/<S-l>` 切换 |
| 缩进参考线（indent-blankline） | 无 |
| 通知美化（noice/nvim-notify） | 无。用 Neovim 原生的 `:messages` |
| 文件树（neo-tree） | mini.files |
| flash.nvim 快速跳转 | 无。用原生 `f`/`t`/`/` 搜索 |
| trouble.nvim 诊断列表 | `<leader>sd`（fzf-lua） |
| todo-comments 高亮 | 无 |
| 彩虹括号 | 无 |
| nvim-cmp / blink.cmp | **原生 LSP 补全** |
| nvim-lspconfig | **原生 `vim.lsp.config`** |
| mason（在 nvim 内装 LSP） | **pacman** |
| lazy.nvim | **原生 `vim.pack`** |
| lualine 状态栏 | 手写的 `lua/core/statusline.lua` |
| nvim-dap 调试 | 无（你说不需要） |
| 自动会话恢复 | 无。但原生 `:mksession` 可用 |
| mini.pairs 自动括号 | 无（你说不需要） |

## 四、排查实战

### 「按某个键出现了奇怪的行为」

```vim
:verbose map <那个键>
```

会告诉你键位定义在哪个文件第几行。三种可能的输出：

```
n  <Leader>ff  * <Lua 123: ~/.config/nvim/lua/plugins/fzf.lua:38>
   ↑ 我们配的，去那个文件改

n  s  * <Lua 88: ~/.local/share/nvim/site/pack/core/opt/mini.surround/...>
   ↑ 插件的，去 lua/plugins/mini-surround.lua 调整或删掉

（什么都没输出，但按了确实有反应）
   ↑ Neovim 原生的，查 :help <那个键>
```

### 「某个功能不工作了」

```vim
:checkhealth            " 全面体检
:checkhealth lsp        " LSP 状态
:messages               " 看有没有报错信息
:ConformInfo            " 格式化工具状态
```

### 「想知道某个选项现在是什么值」

```vim
:set shiftwidth?        " 查值
:verbose set shiftwidth?  " 还告诉你是哪个文件设的
```

### 「怀疑是插件的问题」

把 `lua/plugins/` 里那个插件的 `require` 注释掉，重启看问题是否消失。
更彻底的：`nvim --clean` 完全不加载配置，如果问题还在，那就是 Neovim 本身。
