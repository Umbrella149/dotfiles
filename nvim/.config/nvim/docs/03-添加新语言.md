# 03 · 添加新语言支持

配置一门新语言分两件独立的事，可以只做一件：

| 要什么 | 做什么 | 难度 |
|---|---|---|
| 语法高亮 | 加一行 treesitter parser | 30 秒 |
| 代码智能（补全/跳转/报错） | 装 LSP + 建一个配置文件 | 3 分钟 |
| 自动格式化 | 装工具 + 加一行 | 1 分钟 |

---

## A. 只要语法高亮

打开 `lua/plugins/treesitter.lua`，在 `ENSURE` 列表加一行：

```lua
local ENSURE = {
  'c', 'cpp', 'lua', ...
  'python',        -- ← 新增
}
```

重启 nvim，自动下载编译。完事。

或者临时装一下不改配置：`:TSInstall python`

---

## B. 完整的代码智能（LSP）

### 关键概念

LSP = Language Server Protocol。每种语言有一个独立的后台程序（language server），
Neovim 把代码发给它，它回答「这个变量定义在哪」「这里写错了」。

所以分工是：

- **装 language server** → 系统层面的事，用 `pacman`
- **告诉 Neovim 怎么启动它** → 配置里的事

**本配置不用 `nvim-lspconfig` 插件** —— Neovim 0.11 起自带 `vim.lsp.config`，
配一个 server 只要十来行。

### 三步

#### 第 1 步：用 pacman 装 language server

```bash
sudo pacman -S pyright              # Python
sudo pacman -S rust-analyzer        # Rust
sudo pacman -S gopls               # Go
sudo pacman -S lua-language-server # Lua（改 nvim 配置时很有用）
```

已确认在 Arch 官方仓库的（`sudo pacman -S 包名` 直接装）：

| 语言 | 包名 | server 名字 |
|---|---|---|
| Python | `pyright` | `pyright` |
| Rust | `rust-analyzer` | `rust_analyzer` |
| Go | `gopls` | `gopls` |
| Lua | `lua-language-server` | `lua_ls` |
| TS/JS | `typescript-language-server` | `ts_ls` |
| Bash | `bash-language-server` | `bashls` |
| Markdown | `marksman` | `marksman` |
| Java | `jdtls` | `jdtls` |
| CMake | `cmake-language-server` | `cmake` |
| YAML | `yaml-language-server` | `yamlls` |
| LaTeX | `texlab` | `texlab` |

> **注意 server 名字里的下划线**：`rust_analyzer`（配置里）vs `rust-analyzer`（命令名）。
> 不确定就去查 [nvim-lspconfig 的配置列表](https://github.com/neovim/nvim-lspconfig/tree/master/lsp)——
> 我们不装这个插件，但它的文件名就是标准 server 名，而且里面的内容可以直接拿来用。

#### 第 2 步：新建配置文件

在**配置根目录的 `lsp/` 下**新建文件，**文件名 = server 名**。

> ⚠️ 注意是 `~/.config/nvim/lsp/pyright.lua`，**不是** `lua/lsp/pyright.lua`。
> 这是 Neovim 原生约定的查找路径，放错地方不会生效。

以 Python 为例，`lsp/pyright.lua`：

```lua
-- ============================================================================
-- pyright —— Python 的 language server
-- 安装：sudo pacman -S pyright
-- ============================================================================

return {
  cmd = { 'pyright-langserver', '--stdio' },   -- 怎么启动它（看官方文档）

  filetypes = { 'python' },                    -- 哪些文件类型用它

  -- 「项目根目录」怎么判断：从当前文件往上找，看到这些之一就停。
  -- 这决定了 LSP 的工作范围（比如 grr 找引用时搜哪些文件）。
  root_markers = {
    'pyproject.toml',
    'setup.py',
    'requirements.txt',
    '.git',
  },

  -- 传给 server 的自定义选项。每个 server 支持的不一样，查它的官方文档。
  settings = {
    python = {
      analysis = {
        typeCheckingMode = 'basic',   -- off / basic / strict
      },
    },
  },
}
```

**最小可用版本**其实只要这样（其他都有合理默认值）：

```lua
return {
  cmd = { 'pyright-langserver', '--stdio' },
  filetypes = { 'python' },
  root_markers = { '.git' },
}
```

#### 第 3 步：启用它

打开 `lua/lsp/init.lua`，在 `vim.lsp.enable` 里加一行：

```lua
vim.lsp.enable({
  'clangd',
  'pyright',     -- ← 新增
})
```

重启 nvim，打开一个 `.py` 文件。状态栏右边应该出现 `pyright`。

### 验证与排查

```vim
:checkhealth lsp        " 看 server 有没有启动、挂到了哪些 buffer
:LspInfo                " 0.12 里等价于上面这条（有些版本可能没有）
:lua vim.print(vim.lsp.get_clients())   " 列出当前挂载的所有 client
```

**没启动的常见原因：**

1. `cmd` 里的命令不存在 → 终端里敲 `which pyright-langserver` 确认
2. 文件名 ≠ server 名 → 检查 `lsp/xxx.lua` 的文件名和 `vim.lsp.enable` 里的名字一致
3. 文件放在了 `lua/lsp/` 而不是 `lsp/` → 挪出来
4. `root_markers` 一个都没匹配上 → 加个 `.git`，或者在项目里 `git init`
5. `filetypes` 写错 → 用 `:set filetype?` 看看这个文件实际的 filetype 是什么

## C. 自动格式化

**第 1 步**：pacman 装工具

```bash
sudo pacman -S stylua    # Lua
sudo pacman -S ruff      # Python
sudo pacman -S prettier  # JS/TS/JSON/Markdown/CSS
# Rust 的 rustfmt 随 rustup/rust 一起装了
# C/C++ 的 clang-format 随 clang 一起装了（你已有）
```

**第 2 步**：`lua/plugins/conform.lua` 里加一行

```lua
formatters_by_ft = {
  c = { 'clang-format' },
  cpp = { 'clang-format' },
  lua = { 'stylua' },
  python = { 'ruff_format' },              -- ← 新增
  rust = { 'rustfmt' },                    -- ← 新增
  markdown = { 'prettier' },               -- ← 新增
}
```

conform 内置了 100 多个工具的调用方式，一般只要写工具名。
工具名列表：[conform 支持的 formatters](https://github.com/stevearc/conform.nvim#formatters)

排查：`:ConformInfo`

## D. 语言特定的缩进等设置

新建 `after/ftplugin/<filetype>.lua`：

```lua
-- after/ftplugin/python.lua
vim.bo.shiftwidth = 4
vim.bo.expandtab = true
vim.wo.colorcolumn = '88'
```

记住用 `vim.bo`/`vim.wo`，不要用 `vim.o`。详见 [01-core-原生层.md](01-core-原生层.md)。

## 完整例子：从零加上 Rust

```bash
sudo pacman -S rust-analyzer
```

**`lsp/rust_analyzer.lua`**（注意下划线）：

```lua
-- ============================================================================
-- rust-analyzer —— Rust 的 language server
-- 安装：sudo pacman -S rust-analyzer
-- ============================================================================

return {
  cmd = { 'rust-analyzer' },
  filetypes = { 'rust' },
  root_markers = { 'Cargo.toml', 'rust-project.json', '.git' },

  settings = {
    ['rust-analyzer'] = {
      cargo = { allFeatures = true },
      checkOnSave = true,           -- 保存时跑 cargo check，报出编译错误
      check = { command = 'clippy' }, -- 用 clippy 而不是 check（更严格的建议）
    },
  },
}
```

**`lua/lsp/init.lua`**：

```lua
vim.lsp.enable({ 'clangd', 'rust_analyzer' })
```

**`lua/plugins/treesitter.lua`** 的 `ENSURE` 加 `'rust'`

**`lua/plugins/conform.lua`** 加 `rust = { 'rustfmt' }`

**`after/ftplugin/rust.lua`**（可选）：

```lua
vim.bo.shiftwidth = 4
vim.bo.expandtab = true
vim.wo.colorcolumn = '100'
```

重启，打开一个 `.rs` 文件。搞定。

## 附：clangd 的项目配置（C/C++ 专属）

clangd 需要知道你的编译参数（头文件路径、C++ 标准、宏定义），否则会到处报
「找不到头文件」。它从项目根目录的这两个文件之一获取：

**CMake 项目** —— 让 CMake 自动生成：

```bash
cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -B build
ln -s build/compile_commands.json .
```

**手写 Makefile 或单文件** —— 手写一个 `compile_flags.txt`，一行一个参数：

```
-std=c++20
-I./include
-Wall
```

两个都没有时 clangd 用默认参数，简单文件能用，复杂项目会误报。
