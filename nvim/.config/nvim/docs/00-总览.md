## 一分钟看懂目录结构

```
~/.config/nvim/
│
├── init.lua              ← 入口。只有 10 行 require，一眼看完全貌
│
├── lua/core/             ← 【第一层】纯原生，零插件依赖
│   ├── options.lua           行号、缩进、搜索等选项
│   ├── keymaps.lua           不依赖插件的键位
│   ├── autocmds.lua          自动命令（保存时删行尾空格等）
│   ├── treesitter.lua        语法高亮（原生功能）
│   ├── diagnostic.lua        报错/警告长什么样
│   └── statusline.lua        底部状态栏（手写，不用 lualine）
│
├── lua/plugins/          ← 【第二层】插件，一个插件一个文件
│   ├── init.lua              插件清单（立即加载的）
│   ├── deferred.lua          插件清单（延迟加载的）
│   ├── catppuccin.lua        主题
│   ├── treesitter.lua        下载语言 parser
│   ├── fzf.lua               模糊查找
│   ├── gitsigns.lua          git 行内标记
│   ├── mini-files.lua        文件浏览器
│   ├── mini-surround.lua     引号括号操作
│   ├── which-key.lua         按键提示
│   └── conform.lua           代码格式化
│
├── lua/lsp/init.lua      ← 【第三层】LSP 通用行为（补全、键位）
├── lsp/clangd.lua        ← 每个语言一个文件（注意：不在 lua/ 下面！）
│
├── after/ftplugin/       ← 按文件类型的局部设置（原生机制）
│   ├── c.lua  cpp.lua  lua.lua  markdown.lua
│
├── nvim-pack-lock.json   ← 插件版本锁定，建议纳入 git
└── docs/                 ← 你正在看的文档
```

### 这个结构的核心设计

**三层是可以逐层剥离的：**

- 把 `lua/plugins/` 整个删掉 → 依然是一个好用的编辑器（有语法高亮、LSP、完整键位），只是没有主题和模糊查找
- 再把 `lua/lsp/` 也删掉 → 依然能正常编辑代码
- 只留 `init.lua` + `lua/core/` → 这是 100% 原生的 Neovim

**所以当你遇到一个搞不懂的行为，排查顺序是：**
1. 先看 `lua/core/` —— 是我配的原生选项吗？
2. 再看 `lua/plugins/` —— 是某个插件干的吗？
3. 都没有 → 那就是 Neovim 自带的（详见 [06-原生还是插件.md](06-原生还是插件.md)）

## 装了哪些插件（一共 8 个）

| 插件 | 干什么 | 不装会怎样 |
|---|---|---|
| catppuccin | 配色主题 | 只有 Neovim 默认的丑配色 |
| nvim-treesitter | 下载语言 parser | C/Lua/Markdown 仍有高亮（内置），C++ 等没有 |
| fzf-lua | 模糊查找文件和内容 | 只能用 `:e 路径` 和 `:grep` |
| gitsigns | 行内 git 标记 | 看不到哪几行改过 |
| mini.files | 文件浏览器 | 只能用 `:e 目录` |
| mini.surround | 快速加/删/换引号括号 | 手动改 |
| which-key | 按 leader 后弹提示 | 得自己记键位 |
| conform | 代码格式化统一入口 | 得手动跑 clang-format |

**明确没装**（LazyVim 里有但这里没有）：启动页、buffer 顶栏、缩进参考线、通知美化、
文件树（用 mini.files 替代）、mason（用 pacman 替代）、nvim-cmp/blink（用原生补全）、
nvim-lspconfig（用原生 `vim.lsp.config`）、lazy.nvim（用原生 `vim.pack`）、DAP 调试。

## 启动速度

实测数据（你的机器，headless 模式）：

| 场景 | 耗时 |
|---|---|
| `nvim --clean`（完全无配置的理论下限） | ~5 ms |
| **本配置，界面出现** | **~23 ms** |
| 本配置，全部插件加载完成 | ~49 ms |

**为什么这么快 —— 延迟加载是怎么做的**

你原来担心 `vim.pack` 没有懒加载。实际上懒加载不是插件管理器的魔法，就 6 行代码
（在 `lua/plugins/init.lua` 里）：

```lua
vim.api.nvim_create_autocmd('UIEnter', {   -- 界面画完了
  once = true,
  callback = function()
    vim.schedule(function()                 -- 再等主循环空闲一拍
      require('plugins.deferred')           -- 这时才加载其余插件
    end)
  end,
})
```

这就是 LazyVim 里 `VeryLazy` 事件的原理。启动时只加载主题（否则会看到画面闪一下变色），
其余 7 个插件在你还没看清屏幕时就在后台加载好了。

如果以后插件多到延迟加载都变慢，还有一招：`vim.pack.add({..., load = false})` 可以
让某个插件先下载但完全不加载，等你第一次用到时再 `vim.cmd.packadd('插件名')`。

## 日常维护命令

```vim
:lua vim.pack.update()                   " 更新所有插件（先看 diff，:w 确认 / :q 放弃）
:lua vim.pack.update({'fzf-lua'})        " 只更新一个
:lua vim.pack.update(nil,{offline=true}) " 离线查看装了什么、什么版本
:TSUpdate                                " 更新语法 parser
:checkhealth                             " 全面体检，配置有问题先跑这个
:checkhealth lsp                         " 只看 LSP 状态
:ConformInfo                             " 排查「为什么没格式化」
```

## 版本控制（建议做）

```bash
cd ~/dotfiles
git init
git add -A
git commit -m "nvim 配置初始版本"
```

配置改坏了随时 `git diff` 看改了什么、`git checkout` 回退。
`nvim-pack-lock.json` 一定要提交进去 —— 它记录了每个插件的确切版本，
换机器时能装出一模一样的环境。
